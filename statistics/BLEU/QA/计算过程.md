可以。这个例子很适合手工推演，因为 `tokenize='zh'` 基本会把中文字符逐字切开，中文标点也会成为 token；非中文部分再按类似 `13a` 的规则处理。:chatgpt-content-reference{index="0"}

你的代码最后应得到大致：

```text

各 n-gram 精度: [95.23809523809524, 77.77777777777777, 66.66666666666667, 50.0]
长度惩罚 BP: 0.9534969548334766
系统长度 / 参考长度: 21 / 22
```

下面完整推演。

## 1. `tokenize='zh'` 之后是什么样

SacreBLEU 的 `zh` tokenizer 会把中文字符分别切开。:chatgpt-content-reference{index="1"}

### 系统输出

| 句子 | 原句 | Token 化 | 长度 |
|---|---|---|---:|
| S1 | 狗咬了那个人。 | 狗 / 咬 / 了 / 那 / 个 / 人 / 。 | 7 |
| S2 | 这并不令人惊讶。 | 这 / 并 / 不 / 令 / 人 / 惊 / 讶 / 。 | 8 |
| S3 | 猫在垫子上。 | 猫 / 在 / 垫 / 子 / 上 / 。 | 6 |

所以系统总长度：

\[
c=7+8+6=\boxed{21}
\]

---

## 2. 两组参考译文的长度

你的 `refs` 结构是：

```python
refs = [
    [ref1_sentence1, ref1_sentence2, ref1_sentence3],
    [ref2_sentence1, ref2_sentence2, ref2_sentence3],
]
```

也就是有 **2 组 reference corpus**。

| 句子 | Reference 1 | 长度 | Reference 2 | 长度 | 系统长度 |
|---|---|---:|---|---:|---:|
| S1 | 狗咬了那个人。 | 7 | 那只狗咬了那个人。 | 9 | 7 |
| S2 | 这并不意外。 | 6 | 没有人感到惊讶。 | 8 | 8 |
| S3 | 垫子上有一只猫。 | 8 | 猫蹲在垫子上。 | 7 | 6 |

BLEU 有多个参考时，不是把参考长度加起来，而是对**每一个系统句子选择长度最接近的参考句**。

所以：

| 系统句 | 系统长度 | 参考长度 | 选择 |
|---|---:|---|---:|
| S1 | 7 | 7, 9 | 7 |
| S2 | 8 | 6, 8 | 8 |
| S3 | 6 | 8, 7 | 7 |

因此有效参考长度：

\[
r=7+8+7=\boxed{22}
\]

所以：

\[
\boxed{c=21,\quad r=22}
\]

# 3. 1-gram 精度

先逐句计算。

### S1：`狗 咬 了 那 个 人 。`

参考 1 完全一样：

```text
狗 咬 了 那 个 人 。
```

所以：

\[
7/7
\]

全部匹配。

---

### S2：`这 并 不 令 人 惊 讶 。`

两个参考：

```text
R1: 这 并 不 意 外 。
R2: 没 有 人 感 到 惊 讶 。
```

逐个 token：

| Token | 是否能在某个参考中找到 |
|---|---|
| 这 | ✓ R1 |
| 并 | ✓ R1 |
| 不 | ✓ R1 |
| 令 | ✗ |
| 人 | ✓ R2 |
| 惊 | ✓ R2 |
| 讶 | ✓ R2 |
| 。 | ✓ |

所以：

\[
7/8
\]

这里有一个很重要的 BLEU 特性：

> 不要求所有匹配都来自同一个 reference。

`这、并、不` 可以从 R1 匹配，而 `人、惊、讶` 可以从 R2 匹配。

---

### S3：`猫 在 垫 子 上 。`

参考：

```text
R1: 垫 子 上 有 一 只 猫 。
R2: 猫 蹲 在 垫 子 上 。
```

所有单字都能在参考中找到：

\[
6/6
\]

---

所以整个 corpus：

\[
\text{match}_1=7+7+6=20
\]

总 1-gram：

\[
\text{total}_1=7+8+6=21
\]

因此：

\[
p_1=\frac{20}{21}
=0.952381
\]

即：

\[
\boxed{p_1=95.238\%}
\]

# 8. BP 长度惩罚

现在：

\[
c=21
\]

\[
r=22
\]

由于：

\[
c<r
\]

说明系统翻译比参考翻译短，所以要进行 brevity penalty：

\[
BP=e^{1-r/c}
\]

代入：

\[
BP
=
e^{1-\frac{22}{21}}
\]

\[
=e^{-1/21}
\]

\[
\boxed{BP\approx0.953497}
\]

所以：

```text
长度惩罚 BP: 0.9534969548
```

同时：

\[
ratio=\frac{c}{r}
=\frac{21}{22}
=0.954545
\]

输出时显示：

```text
ratio = 0.955
```

# 9. n-gram 几何平均

标准 corpus BLEU：

\[
BLEU
=
BP\cdot
\exp
\left(
\frac14
\sum_{n=1}^4\ln p_n
\right)
\]

这里使用小数而不是百分数：

\[
p_1=\frac{20}{21}
\]

\[
p_2=\frac{14}{18}
\]

\[
p_3=\frac{10}{15}
\]

\[
p_4=\frac6{12}
\]

因此几何平均为：

\[
G=
\left(
\frac{20}{21}
\times
\frac{14}{18}
\times
\frac{10}{15}
\times
\frac6{12}
\right)^{1/4}
\]

首先乘起来：

\[
\approx
0.2469136
\]

开四次方：

\[
G\approx0.704914
\]

也就是说，不考虑长度惩罚时：

\[
70.4914
\]

# 10. 最终 BLEU

乘上 BP：

\[
BLEU
=
0.95349695\times0.70491418
\]

\[
\approx0.67213352
\]

乘 100：

\[
\boxed{BLEU\approx67.21}
\]

因此完整结果就是：

| 项目 | 结果 |
|---|---:|
| 系统长度 \(c\) | **21** |
| 有效参考长度 \(r\) | **22** |
| \(p_1\) | **95.238%** |
| \(p_2\) | **77.778%** |
| \(p_3\) | **66.667%** |
| \(p_4\) | **50.000%** |
| 几何平均 | **70.491%** |
| BP | **0.953497** |
| **最终 BLEU** | **67.213 ≈ 67.21** |

所以可以把整个计算压缩成一条公式：

\[
\boxed{
BLEU
=
100
\times
e^{1-\frac{22}{21}}
\times
\left(
\frac{20}{21}
\frac{14}{18}
\frac{10}{15}
\frac6{12}
\right)^{1/4}
=
67.21
}
\]

这个例子还有一个非常值得注意的地方：**corpus-level BLEU 是先把整个语料中的 n-gram 匹配数和总数累加，再计算 precision，而不是先分别算三个句子的 BLEU 再取平均。** 这正是 `corpus_score()` 的核心。
