chrF 中 **n-gram 的匹配不是按位置一一对应匹配**，而是类似 BLEU 的 **集合计数匹配（更准确说是 multiset / bag-of-n-grams + clipped count）**。

也就是说：

> 只要预测句中的某个 n-gram 在参考句中出现，就算匹配；但重复出现时，最多只能匹配参考中出现的次数。

## 3. 做 clipped matching

规则：

\[
match(x)=\min(count_{hyp}(x),count_{ref}(x))
\]

例如：

---

### `Th`

预测：

```
Th ×1
```

参考：

```
Th ×1
```

匹配：

\[
min(1,1)=1
\]

---

### `he`

预测：

```
he ×2
```

参考：

```
he ×2
```

匹配：

\[
min(2,2)=2
\]

---

### `at`

预测：

```
at ×2
```

参考：

```
at ×3
```

只能匹配：

\[
min(2,3)=2
\]

预测里两个 `at` 全部匹配。

---

### `ti`

预测：

```
ti ×1
```

参考：

没有：

```
ti
```

所以：

\[
min(1,0)=0
\]

不匹配。

---

### `so`

同理：

预测：

```

```

参考没有：

## 注意一个容易误解的地方

很多人会以为：

```
预测:
Th he ec ca at ti ...

参考:
Th he ec ca at ts ...
```

因为 `ti` 后面不同，所以后面都不匹配。

这是错误的。

chrF **不看上下文位置是否一致**，它只问：

> 这个 n-gram 在参考里面有没有出现？

例如：

预测：

```
cat
```

参考：

```
dog cat
```

字符 2-gram：

预测：

```
ca
at
```

参考：

```
do
og
gc
ca
at
```

那么：

```
ca ✓
at ✓
```

都会匹配。

---

所以 chrF 的匹配逻辑可以总结为：

\[
\boxed{
\text{生成 n-gram → 统计出现次数 → 与参考 n-gram 做 clipped count 匹配}
}
\]

不是：

\[
\boxed{\text{第 i 个字符和参考第 i 个字符比较}}
\]

这也是为什么 chrF 对词序的小变化、词形变化、拼写变化比较鲁棒。
